# Live Wire editorial preview manifest (v2)

`livewire-editorial-read.manifest.json` describes the read-only editorial
evidence preview served at `/api/stories`, `/api/story`, `/api/receipts`,
`/api/corrections`, and `/api/capabilities`. It lists the operations the
preview accepts, the shapes it returns, and what it never does.

The record is deliberately `degraded`: fixture reads work, but there is no
model work, external action, mutation, or spend, and no production authority.
Any change to that boundary requires a new manifest version.

The file is generated by `scripts/build_gate1_capability.py` and must match it
byte for byte; `app/gate1_capability.py` refuses to serve a hand-edited copy.

This manifest requires `livewire.editorial.v2`. V2 is a breaking successor to
v1 because Evidence now binds exact `targetText`; it makes no v1 backward
compatibility claim. The v1 JSON Schemas remain checked in unchanged.

The referenced v2 JSON Schemas prove individual shape only. Semantic validity
also requires the Pydantic models, `editorial.policy`, and every suite named in
the manifest's `semanticValidation.requiredTests` (contracts, isolated server,
platform boundary, and public edition). Schema-only validation is never
enough to publish anything.

It grants no invocation or write access, is not a certified Routine, and
registers nothing with any external system.
